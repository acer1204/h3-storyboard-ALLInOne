# 工程圖標註擷取

SAM3 找位置，視覺模型讀內容。兩段分開是刻意的：SAM3 只會分割、給不出文字；
視覺模型直接讀整張大圖時標註太小又埋在線條裡，容易漏。先框再逐框放大讀，
每個裁切都是乾淨的小圖。

## 用法

```
python read_drawing.py <圖檔>
python read_drawing.py <圖檔> --boxes-only          # 只定位，先看框準不準
python read_drawing.py <圖檔> --prompt "text:80" --thr 0.25
```

輸出三個檔（與來源同名）：`-標註.png`（框位置圖）、`-標註.csv`、`-標註.json`。
每列是一個標註的中心座標、外接框與讀到的文字。

## 實測過的設定

| | 值 | 為什麼 |
|---|---|---|
| 提示詞 | `number:80, text:40` | `:N` 是該類別的實例上限，**不寫只會回 1 個**。`number` 只認純數字，`ø25X8 孔`、`QTY=2 PCS` 這種帶符號或整串的要靠 `text` |
| 閾值 | `0.10` | 0.25 時 45 框、0.10 時 74 框。工程圖的字細，寧可多抓再去重 |
| 精修 | `1` | 文字是方塊，不需要細緻邊界 |
| 個別 mask | `true` | 關掉只會拿到一張聯集遮罩，無法逐框裁切 |
| 裁切放大 | `4x` | 小字直接丟給模型讀不準 |

提示詞比較（3309×2339 的那張，IoU ≥ 0.3 才算框中）：

| 提示詞 | 可用框 | `ø25X8孔` | `QTY=2PCS` |
|---|---|---|---|
| `number:80` | 71 | 0.00 ✘ | 0.08 ✘ |
| `text:80` | 53 | 0.77 ✔ | 0.78 ✔ |
| `annotation:40` | 7 | 0.80 ✔ | 0.77 ✔ |
| `note:40` | 8 | 0.00 ✘ | 0.38 ✔ |
| **`number:80, text:40`** | **107** | **0.77 ✔** | **0.78 ✔** |

`annotation` 框最準但只有 7 個可用框，會漏掉幾乎所有純數字。兩個都要。

## 實測結果

41 個人工清點的標註，對上 38 個（93%）。SAM3 定位 24s，逐框判讀約 1.2s/框。

**旋轉 90° 的直式標註（200／175／100／143／245）全部讀對。**

### 重疊合併

SAM3 對同一個標註會回好幾個範圍不同的框，有時還把一個切成兩段（`R140` → `R1` + `140`）。
單用 IoU 去重擋不住這種**包含關係**（片段被完整框包住時 IoU 很小），所以改成
「重疊就敲成聯集，反覆做到不再變動」。

107 個原始框 → IoU 去重 53 個 → **合併 45 個**，兩個目標的框準度完全沒退。
碎片（`R1`／`140`／`ø22`／`M12`）全部消失。

代價是**靠太近的兩個標註會被併在一起**：左側上下相鄰的 `80` 和 `25` 變成一個框，
讀成 `80 25`。要分開得調 `clean()` 的 `thr`，或改成只在同一列時才合併。

### 已知弱點

- `ø135` 的 `ø` 被框切掉，只讀到 `135`。
- 細線圖上 0 和 8 會混。
- 相鄰標註可能被合併（見上）。

批次處理的話值得再調；偶爾查一張圖的話，93% 配人工複核就夠。

### 速度會被 GPU 爭用拖垮

兩段用的是不同模型。同一張卡上輪流跑時，SAM3 跑完會把視覺模型擠出 VRAM，
下一次判讀得先花約 20 秒重載，之後也一直在搶。

實測同一張圖：視覺模型常駐時 **1.2s/框**，被擠掉之後 **9.25s/框**。

ComfyUI 與 LLM 分開部署在不同機器時不會有這個問題。

## 需要

- ComfyUI 跑著，且 `models/checkpoints/sam3.1_multiplex_fp16.safetensors` 在位
- llama-server 跑著，模型要有 multimodal 能力
- 路徑可用環境變數改：`COMFY_URL` `LLAMA_URL` `COMFY_INPUT` `COMFY_OUTPUT` `SAM3_CKPT` `VLM_MODEL`

## 只想看框在哪

`workflows/SAM3_工程圖文字定位.json` 拖進 ComfyUI，把節點 2 換成你的圖，按執行。
`DrawBBoxes` 會把紅框畫在原圖上，一張圖看完，存到 `output/dwg_boxes_xxxxx.png`。

畫框只需要 `bboxes` 輸出，所以那個工作流的「個別 mask」是關的——腳本要逐框裁切才需要開。

（`CropByBBoxes` 看起來能一次吐出所有裁切，但實測餵 SAM3 的 bboxes 只回 1 張，
沒有深究，腳本仍用自己裁切。）
