# 網頁介面

```
tools/drawing-ocr/.venv/Scripts/python server.py
```

然後開 http://127.0.0.1:9995 。自己的 `.venv`，只需要 opencv 與 numpy。

## 用途

只做**定位**——把 SAM3 找到的標註畫成紅框，讓人調提示詞與門檻。約 40～60 秒。
判讀（LLM）那段不在這裡，之後再說。

## 操作

拖一張圖進去 → 按「開始定位」→ 看紅框。

左側可調三個值。**改後兩個不用重跑 GPU**，合併是在瀏覽器裡做的，即時反應：

| 參數 | 預設 | 作用 |
|---|---|---|
| 提示詞 | `number:80, text:40, symbol:30` | 逗號分隔多類別，`:N` 是該類別最多抓幾個 |
| 閾值 | 0.10 | 低＝抓得多。要重跑 |
| 合併強度 | 0.30 | 低＝更容易把重疊的框併成一個。0 ＝不合併 |
| 跨行判定 | 1.5 | 見下 |

右側可滾輪縮放、拖曳平移。點左側清單裡的項目會把那個框帶到畫面中央。

兩個下載鈕：**紅框圖 PNG**（全解析度，框上有編號）與**框座標 CSV**。

## 為什麼提示詞要三個

各類別只認自己那一種，缺一個就漏一批：

| 提示詞 | 抓得到 | 抓不到 |
|---|---|---|
| `number` | 890、150、R140… | `ø25X8 孔`（有符號＋中文）、`QTY=2 PCS`（整串） |
| `text` | 上面那兩個 | 表面粗糙度的 ▽▽▽ |
| `symbol` | ▽▽▽ | 幾乎所有數字 |

實測（3309×2339 那張，IoU ≥ 0.2 算框中）：

| 提示詞 | 原始框 | `ø25X8孔` | `QTY=2PCS` | 右下 ▽▽▽ |
|---|---|---|---|---|
| `number:80` | 71 | ✘ | ✘ | ✘ |
| `number:80, text:40` | 107 | ✔ | ✔ | ✘ |
| **三個都加** | 143 | ✔ | ✔ | **✔** |

`symbol` 的 30 不是隨便寫的：改成 12 就掉了右下那個 ▽▽▽（119 框 vs 128 框）。
需要的符號排在後面，前面是孔的圓圈與中心記號。

**`:N` 不能省**：不寫只會回 1 個，這是最容易踩的坑。

## 跨行判定在解什麼

SAM3 偶爾會回一個歪掉的長框，同時壓在上下兩個不同的標註上。它自己就是一個輸出框，
之後裁切判讀會讀成「80 25」。

分辨的依據是內部框的間距：同一行的字間距小、跨行的大。實測那張圖——

| | 內部框間距 | 相對中位字高（38px） |
|---|---|---|
| `QTY=2 PCS`（真標註） | 水平 43、垂直 0 | 1.13 倍 |
| 歪掉的長框 | 水平 0、垂直 102 | 2.7 倍 |

所以門檻設 1.5 倍：兩邊都對。設 0.8 會連 `QTY=2 PCS` 一起殺掉，設 0 則不檢查。

## 已知狀況

- `ø135` 的 `ø` 常被框邊切掉。
- 加了 `symbol` 之後框數從 107 漲到 143，合併後 63 個（原本 46），多出來的是符號與線條。
- 跑起來會佔 GPU。同一張卡上 ComfyUI 正在算圖時會變慢。

## 速度

一張 3309×2339 的圖，原本 55 秒。拆開來看，偵測本身只佔 3 秒：

| 設定 | ComfyUI | 回讀 | 合計 | 合併後框數 |
|---|---|---|---|---|
| 原本：refine=1、個別遮罩 | 47.7s | 7.4s | **55.1s** | 63 |
| refine=0、個別遮罩 | 26.0s | 5.7s | 31.7s | 63（與原本逐一相同） |
| refine=0、不要遮罩 | **2.9s** | 0.1s | **3.0s** | — |

兩件事在燒時間，而且燒的都是我們用不到的東西。

`refine_iterations` 會把**每一個**偵測結果再送進 SAM decoder 跑一次 1008×1008
的細修。150 個偵測就是 150 次額外前傳，為的是讓遮罩邊緣更貼合——然後我們把它
壓成一個矩形丟掉。關掉之後合併結果 **63 個框逐一對得上**，差 22 秒。

`individual_masks` 更貴。143 個偵測、3309×2339 的圖，那是 [143, 2339, 3309] 的
浮點張量（4.4GB），轉成 RGB 再膨脹三倍，編成 143 張全解析度 PNG 寫到磁碟，
再讓這邊讀回來每張跑一次 `nonzero` 反推出外接矩形。佔掉 54 秒。

而 `SAM3_Detect` 本來就有第二個輸出 `bboxes`，裡面就是框，而且已經換算回原圖
座標。遮罩那整條路是繞遠路去拿手上已經有的東西。

### 取框節點

ComfyUI 沒有節點能把 BoundingBox 送出來，所以 `comfy-node/` 補了一個：

```
xcopy /E /I comfy-node "<ComfyUI>\custom_nodes\drawing_boxes"
```

然後**重開 ComfyUI**。節點不碰 GPU、不產生檔案，框以 JSON 走 `/history` 回來。

不裝也能跑。`has_box_node()` 探不到就自動退回遮罩路線，介面會標「慢路」。

### 試過但沒有採用的

**縮小輸入圖**。偵測器內部反正把圖壓成 1008×1008（`nodes_sam3.py` 的
`common_upscale(..., 1008, 1008)`），所以先縮圖不該影響偵測，遮罩也會小好幾倍。
實測縮到 50% 確實快到 9.8 秒——但**掉了 4 個框**（59/63）。既然取框節點能到 3 秒
又一個不掉，就沒有理由收這個損失。

**多執行緒**。回讀那 143 張 PNG 是 CPU 工作，開執行緒有用；但取框之後根本沒有
PNG 要讀，這條路自己消失了。

**省掉多餘的編解碼**。上傳的圖會被 imdecode、imwrite 到 work/、再 imread、
再 imwrite 到 ComfyUI 的 input。看起來浪費，但實測 3309×2339 的 PNG 編碼
0.07 秒、解碼 0.05 秒，全部加起來不到 0.2 秒。不值得為它把流程弄複雜。

**輪詢間隔**。原本每 2 秒問一次 ComfyUI。在 55 秒的工作上無所謂，在 3 秒的
工作上就是平均多等 1 秒。改成 0.25 秒；前端也從 800ms 改成 250ms。
